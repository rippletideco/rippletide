Trace capture, inventory declaration and policy evaluation are separate data paths. Reducing trace capture does not prevent a policy check from receiving the values it must evaluate.

## Defaults by integration

| Integration | Default trace behavior | Content controls |
| --- | --- | --- |
| TypeScript SDK, including instrumented JS/TS MCP | Operational metadata; input/output content withheld | `captureContent: true` on the client, after owner consent |
| Python SDK | Operational metadata; input/output content withheld | `capture_content=True` on the client, after owner consent; prompt inventory needs separate `allow_content_export=True` |
| Codex live hooks | Activity storage off until selected; content withheld when enabled | Setup `--traces`/`--no-traces`; content opt-in via `RIPPLETIDE_CAPTURE_CONTENT=true` in `~/.rippletide/codex.env` |
| Codex history import | Explicit import; content withheld by default | `backfill --capture-content`, or the adapter content setting |

Review the content setting before running an integration on customer data. SDK content capture is off by default; inventory and policy inputs have separate data boundaries.

## SDK content capture

Both SDKs export allowlisted operational metadata by default. Inputs, outputs, arbitrary application attributes and exception messages/stacks are withheld until content capture is enabled.

```ts
const rippletide = new Rippletide({ captureContent: false });
```

```python
rippletide = Rippletide(capture_content=False)
```

Set the option to `true` in TypeScript or `True` in Python only after explicit owner consent. Captured values are bounded, with credential-shaped keys and inline authorization values redacted. This is not a general PII filter. Operation names and correlation identifiers must not contain user content.

The old `captureMode` option and `RIPPLETIDE_CAPTURE_MODE` variable are no longer supported. They do not override content capture or grant consent; remove them from code and deployment settings.

Metadata can still be sensitive. Identifiers, tool names and model names may identify a person or system. Redaction is not a guarantee that all personal or business-sensitive data has been removed.

## Inventory and prompts

Third-party connection declarations send credential names and status, not secret values. Prompt/instruction inventory is distinct from trace payload capture: a TypeScript prompt declaration can send its fallback text even when runtime content capture is disabled. Review what you register.

Python withholds prompt text by default. Enable `allow_content_export=True` only when the prompt owner has approved storing it. Do not put secrets in prompt text or schema descriptions.

## Policy decision data

Before-action parameters and trusted context are sent to Rippletide and stored in the decision audit trail. Before-response checks evaluate the candidate response and request. These policy inputs do not inherit the trace redaction setting. Keep their scope limited to facts needed by the policy.

Result filtering sends the full declared result for transient validation and evaluation. Raw collection/item bodies are not persisted in the result decision; item IDs, fingerprints, decisions, reasons and plan metadata are retained. Python requires explicit `allow_result_export=True`. Runtime traces can separately capture result content when content capture is enabled.

Rules using a model predicate can send the selected field and instruction to the configured model evaluator. Trace discovery analyses captured values, and document discovery/labeling analyses imported text. Only select sources and fields approved for that processing. A trace without captured content cannot later be replayed as if its raw arguments had been retained.

## Codex history and local state

Codex stores activity only when selected with `--traces`. Input/output content is withheld by default. To include bounded tool inputs/results and final response content, set the following in `~/.rippletide/codex.env` after owner consent:

```bash
RIPPLETIDE_CAPTURE_CONTENT=true
```

Setup preserves this setting but does not enable it. Repository and shell `RIPPLETIDE_*` settings do not configure the adapter. Set the adapter value to `false` to withhold content on subsequent runs and history imports.

Backfill reads local Codex rollouts only when explicitly requested, or when you opt into history import during setup. Use `--dry-run --stats` first. Content is withheld unless `--capture-content` is supplied or the adapter setting is exactly `true`. That opt-in can export bounded prompts, patches, command lines and output; the history does not receive retroactive policy decisions.

Removing local instrumentation or hooks does not erase previously stored server evidence. Keep Connection keys and local credential files private; use [API keys](/docs/api-keys) for rotation and revocation.
