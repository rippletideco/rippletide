**Context & actions** shows the inventory your agent declared and the runtime evidence associated with its actions. It answers what the agent is configured to do; [Traces](/docs/runtime-events) show what it reported doing.

## Inspect the inventory

| View | What to inspect |
| --- | --- |
| Actions | Declared tools and schemas, action risks, linked Rules and recorded activity |
| Instructions | Declared prompts and configuration, subject to the integration's content-export settings |
| Connections | Third-party services and credential names/status, never the secret values |
| Mission, when available | A business workflow and declared capabilities for a recognized profile |

Mission is available only for supported, recognized capability profiles. Other agents open their Actions view. MCP servers show the tools relevant to their narrower connection contract.

## Choose a useful action to control

Start from actions associated with recorded human intervention or a meaningful risk. Inspect the tool schema and related traces, then propose or write a Rule for a specific decision. Risk classification is guidance: it never creates a Rule or enables enforcement automatically.

Use **Traces** to inspect the actual case behind a counter. A recorded human review, a matching Rule and a blocked call are different events and should not be treated as interchangeable measures.

## Keep the declaration current

Sync the inventory when the agent starts, or use the repository's existing `rippletide:sync` script through `rippletide connect`. Re-run after changing tools or trusted context. The inventory reflects the last successful declaration; it cannot discover undeclared code automatically.

A changed contract disables active Rule releases that depend on it. Unrelated catalogue changes do not disable every release. Review and recompile affected Rules before reactivating them.

## Configuration versus proof

Visible inventory proves declaration, not a successful live run. SDK agents also need heartbeat, expected tool usage, turn and response-delivery evidence. MCP and Codex have different acceptance contracts. Follow your [connection guide](/docs/quickstart) and inspect `rippletide events --wait` before calling the runtime verified.
