---
title: "Test your rules"
description: "Try rule scenarios in your own runtime and review the recorded decisions."
---

Use the **Rules** page to generate test prompts for a rule, run them through your connected agent, and inspect the resulting decisions. You run the agent through its normal application lifecycle.

## Try a rule

1. [Create a rule](/docs/write-rules), review it, and set its release to **Observe**.
2. Open the rule and select **Testing**. Review the generated **Test prompts**, or choose **Generate tests** if none are available.
3. Check that the prompts represent cases you expect to allow and cases you expect to block. Generated scenarios are suggestions to review.
4. Run the prompts as separate turns in a test environment with safe tool effects. Observe mode lets actions continue, including cases that would be blocked in Enforce.
5. Review the run in [Runtime Events](/docs/runtime-events) and the recorded decisions on the **Rules** page. Confirm both the rule matches and the cases that should pass.

For an MCP server, invoke its guarded tools through your MCP client with representative inputs, then review the same decision evidence.

You can also inspect recent decisions from the CLI:

```bash
rippletide rules decisions --agent <agentId> --limit 20
```

## Refine and verify

If a decision differs from your expectation, inspect the rule, action inputs, and trusted context. Revise the rule or your integration as needed, then repeat the cases. Move a release to [Enforce](/docs/observe-and-enforce) only after reviewing its evidence. For a before-action rule, verify that a blocked call does not invoke the protected tool.
