Core workflows are available from the CLI: connecting, inspecting runtime evidence, and managing rules. Install once:

```bash
npm install -g rippletide-package
```

Every command is then `rippletide <command>`, and all commands accept `--json` for machine-readable output.

## Commands

| Command | What it does |
| --- | --- |
| `login` | Log in via your browser; reuses a valid stored Platform key |
| `logout` | Revoke the current Platform key, then clear the local login |
| `whoami` | Show your account, current workspace, and role |
| `agents` | List the agents on your account |
| `connect [--yes]` | Create or link the current repository, write its CLI connection configuration, and present its setup prompt |
| `connect --print-prompt` | Create or link the repository, write its CLI connection configuration, and print the setup prompt for a coding agent |
| `verify` | Check a repository's CLI configuration and synced inventory from its `.env` (no login needed) |
| `events [<traceId>] [--agent <id>] [--cursor <cursor>]` | List traces, open one, or read the next page |
| `events --wait` | Wait for complete observed runtime evidence: manifest, heartbeat, and turn; MCP also needs a tool call |
| `status` | Account login, project binding, inventory, and runtime evidence at a glance |
| `rules discover [--source <text\|https-url\|@file>]` | Review and batch-create complete discovered rules; `--json` is read-only |
| `rules create --agent <id> --action <key> --effect ALLOW\|BLOCK --input "…"` | Compile and save a disabled plain-English rule |
| `rules discover --agent <id> --activity --include-raw-values --out proposals.json` | Suggest rules from recorded activity, with evidence and replay results |
| `rules save --agent <id> --file proposals.json --proposal <id> [--config '<JSON>']` | Complete any required settings and save a selected suggestion Disabled |
| `business-context <command>` | Upload and version documents, discover rules, and review selected changes |
| `workspaces <command>` | Check your workspace and manage its members and invitations |
| `workspaces use [<id>]` | Choose a workspace through browser approval |
| `rules targets` / `rules list` | Inspect policy targets and rule releases |
| `rules decisions --agent <id> [--limit 20]` | Review recent decisions and get commands to enforce triggered observe releases |
| `rules set-mode --release <id> --mode disabled\|observe\|enforce` | Change one rule release's mode |

`connect` can execute your repository's own `rippletide:sync` and `rippletide:start` scripts, so it asks for confirmation; pass `--yes` only for a repository you trust. It does not launch a coding agent or create those scripts for you. Apply the generated setup prompt in the coding agent you use for the repository.

`login` validates `~/.rippletide/config.json` before starting a browser flow, so
running it again does not accumulate keys. To replace the key or change
accounts, run `rippletide logout` and then `rippletide login`. A validation
failure creates nothing, while a failed logout keeps the current local
credential so revocation can be retried.

## Read evidence and create rules

`rippletide events <traceId> --json` returns the complete retained trace. Content
that was not captured or was redacted remains unavailable. Use `--cursor` with
the next cursor from the previous response to read older traces.

Use `--effect ALLOW` for an Allow rule or `--effect BLOCK` for a Block rule.
Block is the default. Allow applies before an action; rules on results or
responses use Block. If the compiler asks a question, repeat the original
command and add your answer with `--context "…"`.

Activity discovery uses captured inputs and outputs. `--include-raw-values`
gives permission to use them for that request. Review the saved proposals and
supply any required settings through `--config` before saving. New rules start
Disabled.

See [Workspaces](/docs/workspaces#from-the-cli) and
[Business context](/docs/business-context#from-the-cli) for command examples.

To try rule scenarios, follow [Test your rules](/docs/evaluate-improve). Generate prompts in the app, run them in your own runtime, and inspect their decisions.

## Where configuration lives

| Scope | Path | Contents |
| --- | --- | --- |
| Account | `~/.rippletide/config.json` | Endpoint and Platform key |
| Project | `.rippletide/project.json` | Agent ID and name (safe to commit) |
| Runtime | `.env` | `RIPPLETIDE` Connection string and `RIPPLETIDE_PROXY_URL` (never commit) |

The CLI configuration is distinct from the app-based/manual configuration documented in [API keys](/docs/api-keys). Do not add `RIPPLETIDE_AGENT_ID` and `RIPPLETIDE_API_KEY` to a `.env` already managed by `rippletide connect`.

After removing Rippletide instrumentation, disconnect a repository by deleting
`.rippletide/project.json`, removing only `RIPPLETIDE` and
`RIPPLETIDE_PROXY_URL` from `.env`, and revoking its Connection key in the
Platform. `rippletide logout` is separate account-level cleanup: it revokes the
CLI Platform key and clears the local account login.
